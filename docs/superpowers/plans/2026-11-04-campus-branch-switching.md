# Campus/Branch Switching Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. This preserves the maintainer's selected execution method. Steps use checkbox (`- [ ]`) syntax for tracking. Implementation starts after maintainer review of this plan.

**Goal:** Publish a reproducible descriptive comparison of IOS XE, AOS-CX and EOS disclosure and remediation-publication patterns, with source gaps and model uncertainty visible.

**Architecture:** Reuse the existing vendor plugins, bounded archive queue, evidence/revision storage and immutable publication boundary. Add an opt-in Cisco authenticated transport, versioned study/evidence contracts and a pure comparison reducer. Collection, score enrichment and the reader remain separate: readers consume one sanitized generation without upstream access.

**Tech Stack:** Existing Python >=3.11, SQLite, jsonschema, stdlib HTTPS, vanilla JavaScript, pytest and Node. No new runtime dependency; additive migration for quota and enumeration state. Preserve advisory schema v2.

**Spec:** [Approved descriptive-study design](../specs/2026-11-04-campus-branch-switching-design.md). Read both documents before implementing.

## Global Constraints

- Mandatory historical start `2021-01-01`; cutoff `2026-04-07` belongs to the post period. Observation end is explicit and 2026 remains partial. No equivalence verdict, security ranking, causal interpretation or automatic “no difference” conclusion.
- Targets: Catalyst 9200, 9300/9300L, 9400 (C9407R/C9410R), 9500, 9600 (C9606R); CX 6300M/6410; Arista 7050X3/720XP/750 campus chassis. Never alias 750 to 7500. OS-family context and model-qualified subset stay separate.
- Primary vendor and official CVE/NVD/KEV sources only. No automatic model/version matching. Unknown dates/models/totals stay unknown. Fixed-only evidence does not prove affectedness.
- Preserve source URL, retrieval time, SHA-256, normalized revision and literal publisher identities/statuses. Bundles need explicit publisher identity and membership, never same-day inference.
- `CISCO_OPENVULN_CLIENT_ID` / `CISCO_OPENVULN_CLIENT_SECRET` are environment inputs only. No credential/token response, raw private field, customer data or operator receipt enters public assets or source control.
- Keep advisory-v2 properties unchanged; publish only validated typed metrics. Existing `platforms` are string arrays; CPE/purl identifiers retain their meaning. Additional structured scope lives in a separate strict report.
- Preserve the benchmark, old switching plan, frozen studies and original human-review resource/packet. New automated checks remain independent-human-review pending. No initial fix-delay median.
- Keep 512,000-byte target parts, 8,000,000-byte maximum parts, 2,000,000-byte index and 20,000,000-byte default-monitor budget. Archive batches remain at most 20 pages/200 documents.
- No changes to schedules, automatic publication behaviour, hosted workflow permissions, runtime pin, secret wiring or recovery/storage limits without concrete maintainer approval. Default source configs remain unchanged. CLI-first staging is the execution path for this plan.

## Review Focus

1. Credential-bearing redirects, exceptions and interrupted processes must not leak secrets or reset persistent API quotas (Task 2).
2. Moving or inconsistent paginated listings must report unstable enumeration rather than claim complete coverage or lose blocked unknown-date documents (Task 3).
3. Duplicate CSAF product IDs, relationship branches and multi-CVE scores must preserve attribution without broadening model or CVE applicability (Tasks 4–5).
4. A revised old advisory crossing a year/cutoff or joining a bundle must not become an invented new disclosure or remediation event (Task 6).
5. A reader switching from the 24-CVE benchmark to the full study, including empty/failed selections, must keep counts, downloads and publication identity consistent (Tasks 7–8).
