# Opt-in bounded publication v2

The maintainer authorized autonomous continuation without further questions. This is an unactivated code milestone on `feature/publication-v2`, stacked on PR38. It changes representation and bounded consumption, not evidence, applicability, study definitions, review status or hosted configuration.

## Evidence and decision

The original complete-candidate replay remains failed. The private scoped proof preserved the original **129,569,637-byte snapshot byte-for-byte**, all 223 records and all 91,393 distinct claims. It measured a self-contained snapshot archive of **39,038,432 expanded / 5,079,707 gzip bytes**, a complete proposed default read set of **19,162,427 bytes**, and a **265,582,883-byte** site. The earlier all-facts archive still fails at **13,828,808 gzip bytes**; it incorrectly strengthened the archive scope beyond `publication.py:261–272`, which excludes full switching evidence and uses the complete switching summary in the snapshot.

Choose explicit v2 literal tables and bounded token streams, a self-contained archive with exactly the existing snapshot scope, and mandatory separate research roots. Retain ordinary v1 bootstrap/cohort/change/current-evidence parts to avoid rewriting the normal CVE UI. Raising limits, deleting context, changing claim identities, making the archive optional, or merely reconstructing a giant v1 object are rejected. The prototype establishes feasibility for this finite input, not acceptance or capacity of the 966-identity hosted union.

## Opt-in and compatibility

`build(output=None, *, publication_format="v1")`, `publish(..., publication_format="v1")`, `write_bundle(..., publication_format="v1")`, and `target_import_stage.stage(..., publication_format="v1")` accept only `v1|v2`. Add `--publication-format` only to local `snapshot` and `target-import stage`; default is v1. Do not introduce an environment setting. Collection jobs, hosted wrapper, workflow dispatch inputs, source pin, schedules and permissions remain unchanged.

V1 generation, index, receipt and reader paths remain unchanged. Updated readers accept both versions; an old reader encountering opt-in v2 must fail explicitly, not fall back to incomplete data. V2 stage context/request/result use explicit version 2 and `publication_format:"v2"`; preserve existing v1 shapes. Worker selection comes from the validated stage argument/context/request, never ambient variables or self-reported output. `verify(..., publication_format="v1")` and `validate_result(..., publication_format="v1")` validate the expected version/format and reject mismatches. A v2 candidate receipt also binds `archive_scope:"snapshot-v1"`.

## Frozen wire contract

New closed schemas: `schemas/static-index-v2.json`, `schemas/publication-v2.json` (definitions for catalog, parts, roots, ranges, routes and archive), `schemas/switching-overview-v2.json`, `schemas/target-import-context-v2.json`, and `schemas/target-import-result-v2.json`. Existing advisory-v2 and switching v1 semantic schemas remain authoritative. Extend the existing browser-contract generator; do not hand-maintain a second schema copy.

**Paths and identity.** `manifest.json` retains the complete physical file inventory and generation hashes. `data/index.json` has version 2 and the existing publication/generated-at/bootstrap/cohorts/changes/current-evidence fields; those ordinary parts retain their v1 envelope. Its additional `publication_v2` descriptor points to `publication-v2.json`. Do not supply a misleading legacy `full` or legacy switching capability. All new content-addressed parts use `data/v2/<sha256>.json` and envelope `{schema_version:2, publication, generated_at, kind, data}`. Part `kind` is one of `strings`, `shapes`, `tokens`, `root`, `claim_routes`, `record_routes`, `ranges`, `overview`, or `archive`; each has closed kind-specific data. Descriptors remain `{path,sha256,bytes}`. Path strings are relative and closed; reject traversal, URI schemes, queries and encoded aliases.

**Catalog.** `publication-v2.json` contains `{schema_version:2, representation:"publication-catalog", publication, generated_at, codec:"json-token-v1", strings, shapes, roots, routes, switching, archive}`. `strings` and `shapes` are ordered `{part,first,count}` descriptors covering contiguous table indices. `roots` maps safe logical names to root-part descriptors. Every listed root is mandatory. Required roots include `snapshot.json`, `runtime-snapshot`, `switching-evidence.json`, `switching-comparison.json`, and every existing public report/evidence view; do not hard-code the laboratory count 251. `routes` contains claim and record route parts. `switching` is `{overview,definition_sha256,kev,diagnostics}`: overview is a part descriptor; KEV and diagnostics are bound ranges for the complete immutable KEV input and evidence score-availability array. `archive` is `{scope:"snapshot-v1",manifest,expanded,gzip}` with descriptors for its scope manifest, expanded archive and gzip.

**Root parts.** Data is `{name,token_count,logical:{bytes,sha256},pages,ranges}`. Pages are ordered `{part,first_token,count,decoded_upper_bound}` descriptors; positions, including repeated equal pages, are significant. Root SHA/length and range `logical_bytes` describe ordered compact UTF-8 logical JSON, preserving field/array order and numeric lexemes; they do not describe ASCII-escaped export bytes. Ranges are `{root,first_token,end_token,logical_bytes,logical_sha256}` with half-open token positions. A range must start/end at one complete node and match the declared type/path in its consuming schema. `ranges` is an ordered array of range-part descriptors; each range part contains `{path,range}` entries, where path is an array of literal object keys/nonnegative safe array indices and range has the shape above. Large routing/range catalogs are ordinary bounded parts, not oversized inline indexes.

**Tokens.** Literal string tables contain only Unicode strings; shape tables contain only ordered arrays of distinct literal object keys. Neither table contains encoded references. Tokens are `[shape_index]` for an object, `[-1,count]` for an array, integer `-(string_index+2)` for a string, literal null/Boolean, or `[-2,"i"|"f",decimal_lexeme]` for a logical number. All indices/counts are non-Boolean safe integers. No untagged logical numbers are accepted. Integer lexemes preserve exact integers, including existing identities above 2^53, through Python integers / browser BigInt where needed; they are never rounded into transport indices. Float lexemes obey JSON number grammar and decode to finite binary64 values; preserve their original lexeme for streaming hashes/exports, including integral floats and negative zero. Shared vectors freeze this behavior before the browser implementation consumes the format.

The sole allowed root alias is `[-3,"switching-evidence.json"]` at `switching-comparison.json`'s `inputs.evidence`, after the producer proves exact equality. The target contains no aliases; all other alias positions/targets are forbidden. The snapshot archive allows no root aliases or external fact references. There is no general object-reference graph.

**Routes.** Claim-route part data is `{base,final_end,rows:[[claim_atom,delta_start,logical_bytes],...]}`. `claim_atom` indexes a literal claim ID. First delta is zero, later deltas positive; recover each end from the next start, and the last from `final_end`. Require strict starts, cross-part contiguity, unique exact claim IDs and membership equality. The producer must first prove every original interval contiguous; otherwise publication fails rather than guessing. Record routes remain explicit `{record_index,first_token,end_token,logical_bytes}` rows. Preserve every original ID, order and interval.

**Archive.** `snapshot-v2.json` and deterministic `snapshot-v2.json.gz` embed all parts/tables/root metadata required to reconstruct every original snapshot field, plus an archive-scope manifest. The archive JSON is `{schema_version:2,representation:"snapshot-archive",publication,generated_at,assets:[{path,sha256,bytes,data},...]}`, where data is the complete declared part envelope. Its archived `archive`-kind scope manifest contains `{scope:"snapshot-v1",root,strings,shapes,record_routes,members,legacy_snapshot}`; root is the snapshot root-part descriptor, members is the exact required descriptor closure excluding the scope manifest itself (no self-hash), and legacy_snapshot is `{bytes,sha256}`. The archive is self-contained; it is not a manifest referring to the site. The scope manifest binds both logical canonical digest/length and the original compact ASCII-escaped snapshot serialization with final newline. Research roots outside the old snapshot remain mandatory site assets, with independent complete-root validation. Full JSON bulk export reconstructs their exact logical data as a stream; no giant compatibility JSON file is required in the published site.

## Consumption bounds and validation

Unchanged limits: **128,000,000 expanded archive bytes; 8,000,000 gzip bytes; 20,000,000 default verified read bytes; 8,000,000 bytes per part; 2,000,000 per index; 1,000,000,000 published site bytes**. A selected logical materialization is independently capped at 128,000,000 bytes. Charge the larger of canonical UTF-8 cost and the actual requested serialization cost, including ASCII escapes, before allocating; a canonical range length never authorizes a larger escaped allocation. Decoder depth is at most 64; target pages are 512,000 encoded / 1,000,000 logical bytes. Recompute actual logical charges from literal values and container/key punctuation; never trust declared decoded sizes. Check before appending/allocating. A record can span pages; a root alias opens another bounded cursor, never a giant parent-page expansion.

Fetch at most six parts concurrently. Bound encoded cache to 16,000,000 bytes with eviction; keep accounting for in-flight buffers separate. Read responses incrementally with an 8 MB overflow sentinel before parsing. Default accounting charges actual bytes, including retries/refetches. Explicit streamed bulk/query work remains bounded per page and selected result; it does not silently redefine the 20 MB default path. Every full-root export/verification also has a hard 1,000,000,000-logical-byte ceiling and a fixed 300-second deadline, shared through alias traversal; stop at the smaller declared output length/ceiling and reject mismatch or timeout. Count emitted bytes in the requested serialization, cancel pending reads on failure/client disconnect, and never reset a budget at a child cursor.

Both implementations reject malformed UTF-8, unpaired surrogates, duplicate JSON keys, duplicate layout keys or duplicate layout definitions, nonfinite numbers, unsafe or Boolean indices, invalid numeric lexemes, bad references/lengths/node boundaries, alias cycles or unauthorized aliases, missing/overlapping/reordered ranges, mixed generations, tampered hashes and paths. Use null-prototype objects or safe property definition for literal keys. No join-then-check, unrestricted `JSON.parse` of a reconstructed root, or global trusted-input cache.

The canonical codec is a pure-stdlib `infrastructure_impact/publication_codec.py`. Ship that exact file in `_standalone/publication_codec.py` by force-include and verify byte identity. The standalone monitor imports this codec, not a fork; no new dependency is needed.

## Producer, runtime and switching behavior

Encode directly from the already validated public logical projection. Encode `snapshot.json` first, so its required literal/shape tables are self-contained prefixes; later research/runtime roots cannot enlarge its required table scope. Do not write the 1.59 GB v1 tree and convert it. Refactor the ordinary-part writer so v2 can reuse its bootstrap/cohort/change/current-evidence work without generating giant legacy study files. Preserve CSV bytes and all independently published semantic views. Build the full snapshot root and archive from exactly the current snapshot projection.

Add a mandatory derived `runtime-snapshot` root: all complete primary/retained records and all non-study snapshot fields, plus an explicitly typed `switching_overview` instead of masquerading as a full summary. Its exact derivation is checked against the full snapshot. Store/open is metadata-only: do not eagerly call `runtime_snapshot()` before parsing a route or cohort. `runtime_snapshot(*, cohort=None, fields=None)` is an explicit bounded selection; a no-cohort whole-view call may stream or fail its materialization bound, but must not make health, metadata or a small-CVE query unavailable. For narrow reads, reuse ordinary cohort/record parts and complete precomputed bootstrap catalogs/denominators; do not pass narrowed records to a reducer that assumes it has global context. The browser likewise selects the cohort before materializing. The current 223-record runtime fitting in 128 MB is not an architectural assumption about the hosted union. Legacy JSON endpoints/exports that promise the complete snapshot or selected v1 document must stream the deferred study field back in; they must not silently return the internal runtime projection as the old document.

V2's default overview is explicitly `representation:"switching-overview"`, schema version 2. It retains display counts, denominators, severity/KEV fields, definition, selection, method and review limitations; deferred claim/event/provenance/membership fields have exact bound range descriptors. Keep affected-CVE identities needed for KEV reevaluation available. The default path reevaluates only clock-dependent KEV fields using the same immutable KEV input and explicit evaluation time; it does not require full claim hydration. Diagnostics remain complete and separately pageable.

For a changed study selection, stream and validate each bounded full claim once, then build a **private reducer projection**, never a purported validated v1 claim. Needed fields are claim/vendor/advisory/CVE/product IDs, family/scope/status/initial date, publisher status, conditionality; event bundle identity/date; remediation category/availability/product IDs/scope-binding; score scope/CVE/version/value/provider/origin/preferred/validation; and vendor rating/scheme/namespace. Also collect **every nested four-field source object** from the full claim for exact selected provenance. Keep missing/null distinctions and candidate membership needed for bundle-event dates even when the initial date is outside the selected window. Discard no fact from the fact store.

Extract the existing pure row/event/selection computation so each language's v1 and v2 paths use the same semantic reducer. Bound projection/accumulator and selected-summary bytes; fail visibly if they exceed 128 MB. Do not feed thin mappings into full v1 schema validation, omit source contexts, prefilter by inferred applicability, or bypass validation with a global cache. Validate resulting v1 summary semantics. Query results must match current `summary(select_report(...))` and CSV for identical options and evaluation time, including conflicting bundle dates, drafts, null/empty CVE selections and stale/unavailable KEV.

The native switching API already returns summary JSON and CSV; retain those contracts. The browser must replace `switchingReport()` → full hydration → `selectReport()` on v2 with bounded `switchingSelection()`. Keep existing 25-item detail UI, using callbacks for claims, sources, status/events and diagnostics. Tie callbacks, cursors and downloads to the accepted generation/selection, not pending controls. Label JSON downloads accurately as summaries/overviews; expose the fact catalog and a local `publication-export --publication DIR --root NAME --output FILE` streaming command for complete inputs.

## Owned interfaces

Python owns metadata-only `PublicationReader(directory, *, limits)` and `PublicationStore.open()`, with `metadata() -> dict`, `runtime_snapshot(*, cohort=None, fields=None) -> dict`, `stream_root(name, serialization="logical") -> Iterator[bytes]`, `iter_claims() -> Iterator[ValidatedClaim]`, `switching_selection(options, *, evaluated_at) -> SwitchingSummaryV1`, and `detail_page(selection, kind, *, row_id=None, cursor=None, limit=25) -> DetailPage`. Codec primitives are `iter_tokens(root)`, `stream_json(root, serialization)`, `materialize_range(range, *, max_bytes)`, and strict descriptor/table/range validation. `DetailPage` is `{items,next_cursor,total}`; cursor is generation/selection/root-bound and cannot select another root.

Browser owns `InfrastructurePublicationV2.open(fetchPart, catalog, identity, limits)` and equivalent metadata-only open, `runtimeSnapshot({cohort,fields})`, `streamRoot()`, `materializeRange()`, `switchingOverview(evaluatedAt)`, `switchingSelection(options,evaluatedAt)`, `switchingClaims(ids)`, and `switchingDetails(selection,{kind,row_id,cursor,limit:25})`. `createStaticDelivery` branches by index version and exposes these through the existing loader; v1 methods retain their behavior. The default view may be an explicit overview; requested JSON export returns the fully equivalent selected v1 summary within its materialization bound.

Browser cohort reads reuse ordinary parts through a generation-bound `limits.cohortReader` capability supplied by `createStaticDelivery`. The catalog-only standalone reader cannot discover ordinary index descriptors; if this capability is absent, `runtimeSnapshot({cohort})` rejects before reading. Whole-root and explicit-field streaming remain available directly. The supplied reader must enforce the same fetch, hash, generation and decoded-size limits and preserve global comparison denominators. It must never fall back to loading the whole runtime root for a small cohort.

## Acceptance

Candidate acceptance still requires audit, every mandatory logical root and physical manifest asset, exact native snapshot/record/claim/provenance and CSV parity, both real monitors, and every size gate. The default monitor verifies the complete claim membership and overview bindings within actual 20 MB reads. Archive verification streams the self-contained exact-snapshot archive within unchanged limits. Native parity compares logical streams to an independently queried public projection, including runtime-root derivation; avoid repeating full-schema/full-materialization work already justified by scoped type-aware evidence.

Two bounded implementation owners follow the plan. Freeze schemas, numeric vectors and interfaces before parallel integration. Each owner gets one fresh scoped review; then run focused cross-language integration and one final review. Only after software and packaging checks pass on frozen Python/schema/browser code, perform **one** retained replay. The real hosted union, merge and activation remain separate and unauthorized by this milestone.
