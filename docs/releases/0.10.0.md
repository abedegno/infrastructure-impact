# v0.10.0 research preview candidate

This candidate packages the source-coverage repairs merged in PR #23. It adds
reviewed public-source parsing and operator diagnostics; it does not establish
complete vendor histories or a fair security ranking.

- Parse the official Aruba 2021 directory and two reviewed signed-text structures,
  preserving shared product scope, per-CVE CVSS and literal source provenance.
- Preserve Arista affected, excluded and investigating products with their exact
  platform/version/configuration scope. Recognize reviewed Arista/Cisco notices
  separately from vulnerability advisories.
- Revisit changed retained notices without network access. Track the actual
  requested and selected inputs, including missing dependencies, so unchanged
  wrappers consume no replay budget and later linked bytes can recover.
- Add `impact coverage-gaps` with explicit database/configuration inputs, a closed
  operator schema, bounded previews and separate source/window totals, current
  parsing, notices, errors and historical attempts. Reporting is read-only.
- Verify example vendor plugin 0.1.9 with declared compatibility through 0.10.

The [dated public acceptance](../research/2026-11-05-coverage-repair-observations.md)
retrieved all 19 documents in the reviewed Aruba directory: two parsed and 17
remained explicitly unsupported. Two reviewed Arista advisories parsed; an Arista
advance notice and a Cisco informational notice retained no own CVE assessments.
The four advisories retain 122 literal claims and four valid source-scoped CVSS
metrics. These are bounded source observations, not portfolio totals or current
live-site contents. Full vendor captures remain outside source and release assets.

Authenticated Cisco history still needs authorized credentials. Exact-model and
some remediation bindings remain unresolved; reviewed Arista HTML scores remain
unavailable. Human evidence review is pending. Counts measure disclosure and
collection coverage, not vendor security quality, cause or concealment.

Advisory schema v2, frozen studies/review resources, dependency pins, source
defaults, schedules, permissions, recovery settings and all delivery/storage
budgets remain unchanged. The opt-in example does not activate a hosted backfill.
Release-history evidence is the next milestone and is not implemented here.

Source publication and hosted activation are separate steps. Follow the
[concrete activation proposal](../rollouts/2026-11-05-coverage-010-activation-proposal.md)
only after its exact candidate is approved. Prior v0.9.1 assets remain immutable.
